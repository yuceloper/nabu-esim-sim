# Nabu Link v0.2
2026-11-18: v0.1 successfully tested on Redmi Note 8 host and Mi Pad 5 client: Vodafone TR, SIM READY (5), voice/SMS capability true, signal 3/4. Capability flags are not call/SMS execution tests.

v0.2: same APK on both devices; manual private IPv4 and random 128-bit session code (32 hex characters). Protocol 2 uses AES-128-GCM with independent random 96-bit IVs, per-connection random client and server challenges bound into role-specific AAD, and encrypted status request/response. The code is not transmitted, is renewed on each host start, and is not persisted. The last successful IP is stored. Poll every 3 seconds after success, retry after 5 seconds on failure. Dark status dashboard. Stop host/client on Activity onStop; keep both screens open. No discovery, background service, persistent pairing, calls, SMS, tethering, or virtual RIL yet. No independent security audit; use trusted LAN only, never forward port 37851. Do not share session code. Upgrade both endpoints together; v1 and v2 incompatible. Build: bash scripts/build-link-apk.sh. Not built or device tested in connector environment. Native research remains separate on feature/vsim-cli.

## v0.3 — Always Connected
Foreground service on both endpoints, non-exported, notification with stop action, live status independent of Activity lifecycle. Android 13 notification permission requested. Session key only in memory, last IP saved; no persistent pairing or automatic discovery yet. Protected Activity (FLAG_SECURE) prevents screenshots via standard Android capture, client input masked and cleared on connect. Host session key visible only in app, never notification. Service START_NOT_STICKY: no restart after process kill or reboot. Screen-off behavior depends on Doze and Xiaomi power management; device testing required. Protocol remains 2. No SMS/call/data bridge yet. No independent security audit. Build compiles all Java sources and includes all generated classes. v0.3 not compiled in connector environment.

## v0.4 — Automatic pairing
Phone starts foreground host and advertises _nabulink._tcp. via Android NSD. Enable one new pairing attempt for 60 seconds; tablet discovers private IPv4 hosts, selects phone, and both users compare and approve the same six-digit code. Ephemeral P-256 ECDH, SHA-256 commitment exchange before public key revelation, transcript-bound HMAC key derivation and approval proofs; status uses existing AES-GCM protocol 2 with a derived 128-bit key. Credentials encrypted at rest using Android Keystore AES-GCM; one peer per role, replace by explicitly approving a new pairing. Forget on both endpoints to revoke. Discovery is unauthenticated; payload exchange requires saved key or explicit matching-code confirmation. No code entry, no IP entry. Saved role resumes when app opens; tablet auto reconnects if discovered IP matches previous IP, otherwise select the discovered phone. Background polling retries current IP, not discovery; no boot auto-start. Trusted local network only, no port forwarding. Custom pairing protocol is experimental and not independently audited; no calls/SMS yet. Both devices must update. Build and device test pending.
